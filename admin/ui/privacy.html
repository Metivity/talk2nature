PRIVATE WORKSPACE · LOCAL PROTOTYPE

How this workspace handles data.

This version is for Raviv’s own synthetic research rehearsal. Real recordings, participant accounts and model training are not enabled.

Updated September 30, 2026.

Google Sign-In

When configured, Sign-In supplies a Google identity token to this server. It checks the token’s signature, audience, issuer, expiry, browser nonce, account identifier, email verification and relevant Workspace domain. Access is restricted to raviv@metivity.com and the bound Google account identifier.

The server stores the account identifier to keep ownership stable. It does not save the Google identity token, profile name or profile picture. This flow requests no Gmail, Drive or Calendar access. Google’s sign-in service handles its own account interaction under Google’s privacy policy.

Sessions and cookies

A necessary cookie holds a random session identifier. The server stores only its hash, a CSRF token, the owner account identifier and an expiry. Access expires after four hours; signing out immediately revokes the session. Expired session rows are cleaned up on a subsequent successful sign-in. A separate sign-in challenge expires after five minutes. These cookies are not advertising or analytics cookies.

Observation metadata

The workspace stores the invented metadata you enter, separate permission choices, review attestations, workflow states and minimal action history. Use made-up animal and session aliases. Do not enter real household details or recordings. Permission to review, permission to train and permission to consider publication are separate; a private release does not publish anything or train a model.

Active data is accessible through authenticated owner routes. This prototype stores a local SQLite file outside the public website and Git history. The file is not encrypted by the application and depends on the host’s disk protection. Hosted encryption, backups and a retention schedule must be configured before real-data use. There is no automatic age-based purge of observation records in this prototype.

Withdrawal and exported copies

Withdrawing an observation removes its active metadata and stored review details and revokes releases containing it. Minimal record IDs and action/time history remain to explain the revocation. Previously downloaded copies, operating-system backups and other external copies require separate deletion; the app cannot recall them. No trained model exists in this version.

Sharing and contact

The public Talk2Nature website does not read this private database. The application sends no observation data to an external AI service and has no advertising or analytics integration. Google receives the information needed to operate Sign-In. Any future participant collection, external processing or public release needs an updated disclosure and the corresponding permissions.
