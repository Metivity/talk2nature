# Talk2Nature roadmap

**Updated:** October 25, 2026. This is a public statement of direction, not a delivery schedule, funding commitment or claim that planned work has happened. We choose the next task from evidence and report delays and negative results honestly.

## Where the project is now

Talk2Nature is an early-stage open-source research-software project with a public evidence library and browser tools for careful animal-sound observation. The Field Companion includes a microphone-free synthetic practice path and local, user-started recording workflows. It does not provide a public research-recording upload service, a trained Talk2Nature animal model or general animal translation. No independent software reproduction, outside-user first-use walkthrough, physical-phone save/reopen result or scientific specialist review is currently established.

## Current priorities

### 1. Prove the first-use workflow works for people

The app already has a plain-language whole-moment path, optional technical details and an invented rehearsal that needs no microphone. On October 25, an isolated headless-Chrome context completed the synthetic save/reopen/discard loop on both the local preview and deployed site at 390 × 844 CSS pixels. That is a maintainer browser check, not a physical-phone result or an outside user's first-use evidence. The remaining checks are a named physical phone and an authorized, uncoached first-time-user walkthrough using invented material only. We will fix observed obstacles before adding more interface features; these checks do not ask anyone to record an animal.

### 2. Make one researcher task reproducible

The repository has versioned synthetic examples, annotation and split utilities, and a researcher start guide. The next evidence is an outside person reproducing or challenging a documented task at an exact revision, followed by validation of one export in a researcher's existing workflow. Record the environment, output, help received and failures. Maintainer-run checks are useful but do not count as independent reproduction.

### 3. Grow the evidence library with provenance

Add a source when it answers a real research or user question. Record what was reviewed, exact version, limitations, and separate rights for the paper, data, code and model weights. Keep source summaries original, link to primary material, and treat a public link or repository as no proof of permission to download, redistribute or train.

### 4. Keep the project useful and findable

Maintain readable contributor routes, tested examples, a versioned software citation, crawlable research pages and accurate sitemap metadata. Use verified user tasks, independent reproductions, support burden and actual contributions to guide priorities. Search impressions, stars and page views can indicate reach, but do not establish research use or scientific impact.

### 5. Select a benchmark only when the evidence is ready

No biological machine-learning benchmark is training-ready. A narrow candidate needs a qualified scientific and evaluation review, permitted and appropriately labeled inputs, a clear unit of analysis, leakage-resistant grouped splits, simple baselines, suitable metrics, a locked test set and a bounded local execution plan. Until those gates pass, work remains literature review, rights review and synthetic software validation. Acoustic detection, identity or context prediction does not by itself establish meaning or communication.

## Gated work

Real animal observations, public data intake, animal-operated interfaces, playback, hosted research access and university field networks require their own scientific question, welfare review, applicable ethics and permits, consent and rights, privacy and location protections, retention and withdrawal rules, and verified storage/security. Public code licensing does not supply those approvals. Do not upload recordings, precise sensitive locations or participant information to public issues.

## Useful contributions now

- Try the microphone-free [Field Companion practice](https://metivity.github.io/talk2nature/app/) and report a confusing step through the [first-use task](https://github.com/Metivity/talk2nature/issues/115). Trying it needs no GitHub account; public issue submission does.
- Reproduce the synthetic examples in the [researcher start guide](docs/RESEARCHER_START.md) and report the exact revision, environment and output.
- Correct a research summary by linking the primary source and stating what you reviewed; do not paste article text or submit audio.
- Review one bounded methods question in the [candidate packet](docs/FIRST_DATASET_REVIEW_PACKET.md). It requests public-source critique only, not data or a partnership commitment.
