# First independent validation cycle

Prepared November 28, 2026. **Kit ready; no test sessions recorded.** This is a software-usability exercise using invented material. It is not animal research, a recruitment approval or proof of scientific usefulness. Use the full [first-use protocol](FIRST_USE_WALKTHROUGH.md) for consent, privacy and observation rules.

## One starting link

https://metivity.github.io/talk2nature/app/

Give the participant only that link and the task below. Keep facilitator instructions and technical checks out of their task sheet.

## Participant card

We are testing how clear the app is, not testing you. This exercise uses invented sounds and needs no microphone, account or personal recording. You can stop whenever you like. We will not record your screen or voice; with your permission, the observer will keep brief coded notes about which steps worked. Those notes will be deleted within 30 days of the session.

**Your task:** find a way to try the app without recording. Finish the practice, add a short note with no personal information, save it, and reopen what you saved. Then explain what the saved session contains and where it went.

There is no need to get every step right. If something is confusing, say so or stop.

## Facilitator card

Before contacting volunteers, obtain the required recruitment authorization. Before each session, obtain voluntary consent and confirm this is the person's first use. A returning tester may help debug but cannot count again as a first-time user. The disclosure above means the comprehension check measures retained understanding after disclosure, not a blinded test of what someone would infer unaided.

Use the same deployed build for all five first attempts. Record the build or exact deployed commit, date, physical phone platform, model/browser and browser versus installed-app mode. Check that the browser is not serving a different cached build. A simulator or desktop viewport does not count as a physical phone. Keep one iPhone and one Android represented among the five.

Read the participant card once. Do not name buttons, explain file formats, point to controls or complete steps for them. If help is requested, record it as assistance; do not convert an assisted run into an unassisted success. Count a consenting first-time participant who begins and gets stuck in the denominator. A withdrawn session has no retained individual record and is reported separately only if the participant permitted that aggregate count.

Observe these milestones:

1. Invented practice started without microphone permission.
2. Practice ended and a short review note added.
3. A file saved and found through the ordinary phone interface.
4. The same saved file reopened and the same note found.
5. The participant identifies invented practice, understands that no real animal was recorded, and explains whether the work was uploaded.

If a microphone prompt, personal file or unexpected real recording appears, stop the exercise. Record the software issue without copying personal data. Keep unknown outcomes unknown. Do not collect names, contact details, recordings, screenshots, device identifiers or verbatim quotations.

## Record and judge the result

Keep individual notes in the private project workspace, not in GitHub issues. Record only a participant code, date, phone/browser and app mode, build, consent/first-use confirmation, last completed milestone, assistance, note-match/comprehension outcomes, unexpected microphone prompt, approximate elapsed time, a short paraphrased issue and deletion date. A code is a pseudonym, not a guarantee of anonymity.

The target is at least **4 of 5** unassisted save/reopen completions and at least **4 of 5** correct explanations that the material is invented. Both mobile platforms must be represented. Report each outcome separately, all observed failures and the tested revision. Five people provide formative product feedback, not population-level validation. Public self-reports from [issue 115](https://github.com/Metivity/talk2nature/issues/115) are useful leads, but do not automatically satisfy this observed protocol.

Select at most three fixes from actual findings. Keep the first-attempt results frozen; report later retests separately with their changed build. Do not recruit more participants merely to replace failures. Publish only aggregate findings and resulting decisions, with no identifying notes or quotations.

## Separate researcher check

Use the existing [researcher kit](RESEARCHER_START.md) and [bat-context methods brief](BAT_CONTEXT_REVIEW.md). The prepared source-author request and separate evaluation-design request remain private, unsent and subject to explicit approval. A source-author clarification is not independent validation. Record what each reviewer actually assessed and any relevant collaboration before characterizing the review.

After the user and researcher evidence is available, write a **go, narrow or defer** decision for one concrete workflow. State who needs it, what existing tools already provide, what Talk2Nature adds and which unanswered question would change the decision. Until then, no study success or model-readiness claim is justified.
